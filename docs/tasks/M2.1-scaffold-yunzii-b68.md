# M2.1 — Scaffold di `yunzii-b68` e `kbdef.h` con i pin dello stock

* **Milestone:** M2 · **Stato:** Pronto · **Effort:** M · **Dipendenze:** M0.1 (chiuso), M1.6 (chiuso, vedi sotto) · **Hardware:** nessuno
* **Branch:** `port/yunzii-b68` (o un branch figlio)
* **Sostituisce** le vecchie M2.1 e M2.2 (unite).

## Obiettivo

Far esistere la scheda nel build system con la **matrice reale ricavata dal firmware stock**: `yunzii-b68_default_smk.hex`
compila, senza ancora toccare pin, LED o radio. Il flash sulla tastiera non è in questo task.

## Dati di partenza (da [yunzii-b68-firmware-stock.md](../keyboards/yunzii-b68-firmware-stock.md))

Matrice **16 colonne × 5 righe** (la B68 ha 5 righe fisiche). Le colonne sono le linee strobe, attive basse, nell'ordine in cui lo stock le scorre:

| Colonna | Pin | | Colonna | Pin |
| --- | --- | --- | --- | --- |
| C0 | P6.0 | | C8 | P5.0 |
| C1 | P6.1 | | C9 | P5.1 |
| C2 | P6.2 | | C10 | P5.2 |
| C3 | P6.3 | | C11 | P5.7 |
| C4 | P6.4 | | C12 | P4.0 |
| C5 | P6.5 | | C13 | P4.2 |
| C6 | P6.6 | | C14 | P4.3 |
| C7 | P6.7 | | C15 | P4.5 |

Righe (ingressi con pull-up), stesse della Air60: **R0 = P7.1, R1 = P7.2, R2 = P7.3, R3 = P5.3, R4 = P5.4**.
`P7.0` è un sesto ingresso che lo stock legge insieme alle righe, ma non è detto che sia una riga: **non** entra nella matrice.
Lasciala fuori da `MATRIX_ROWS` e annotala in un commento (`// P7.0: ingresso letto dallo stock, funzione ignota`). La sonda ci dirà cos'è.
Il numero d'ordine di righe e colonne è provvisorio: la mappa tasto → posizione la fissiamo con il firmware sonda
quando avremo la tastiera in mano. Qui serve solo coerenza interna.

## Cosa fare

1. Crea `src/keyboards/yunzii-b68/` da [`src/keyboards/example/`](../../src/keyboards/example) (stessi file, incluso
   `layouts/default/layout.c`) e registra la scheda: `meson.build` della scheda (`platform: 'sh68f90'`, stesso schema di
   `example`) e `subdir('yunzii-b68')` in [`src/keyboards/meson.build`](../../src/keyboards/meson.build).
2. `kbdef.h`: `MATRIX_ROWS 5`, `MATRIX_COLS 16`, le macro `KB_Rn_Px_y`/`KB_Rn` e `KB_Cn_Px_y`/`KB_Cn` con i pin della
   tabella, nello stesso stile di [`nuphy-air60/kbdef.h`](../../src/keyboards/nuphy-air60/kbdef.h). Aggiungi anche le
   stringhe USB (produttore/prodotto) che preferisci e `VID:PID` = `0x258A:0x010C` solo se non confligge con la build
   (altrimenti lascia quelli di default e segnalamelo).
3. `layout.c`: un layer base e un layer Fn (vuoto va bene) in formato 5×16; la disposizione fisica arriva in M2.5.
4. Il resto è copiato da `example` (stub vuoti). I pin sono ancora tutti "da confermare in banco": mettilo in un
   commento unico in cima a `kbdef.h`.

## Criteri di accettazione

* `meson setup build-b68 -Dbuildtype=release` elenca `yunzii-b68_default_smk.hex` e `…_default_flash`.
* `meson compile -C build-b68 yunzii-b68_default_smk.hex` finisce senza errori né warning nuovi; `check_interrupts` passa.
* I pin in `kbdef.h` coincidono con la tabella (li ricontrollo io riga per riga).
* `meson test -C build` non peggiora (resta solo l'errore noto di `console_buf`).
